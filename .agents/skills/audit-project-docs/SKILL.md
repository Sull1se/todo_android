# 独立文档巡检与纠偏

## 触发与范围

仅在维护者明确提出“全量检查并维护项目文档体系”“全面整理项目文档”“排查文档矛盾与规则漂移”等独立审计请求时使用。普通任务收尾、功能开发后的附带文档同步由 `update-project-docs` 处理，不自动触发本 Skill。

先读 [项目入口](../../../AGENTS.md)、[总索引](../../../docs/index.md)、[当前问题](../../../docs/quality.md) 和 [文档维护规则](../../../docs/documentation.md)。以 `documentation.md` 与项目治理规则为基准逐篇审查，不能仅依赖工具脚本通过。

本 Skill 不授权修复业务应用代码、安装 APK、变更签名或代替手动验收。发现业务实现违背已有需求时如实登记缺陷，严禁通过修改需求或降低标准掩盖实现问题。

## 1. 建立基线与覆盖范围

1. 执行 `git status --short` 并核查近期提交记录，确认工作区起始状态，严格保留既有改动。
2. 运行基线检查：
   ```powershell
   pwsh -NoProfile -File scripts/docs/Manage-Docs.ps1 -Mode Check
   ```
3. 盘点全量知识资产：包括根入口 `AGENTS.md`、产品入口页 `README.md`（维护者决定豁免检查器治理）、`docs/` 下全部 Markdown 文件、`docs/archive/` 下所有归档方案与技术记录（存在时含其归档索引），以及 `.agents/skills/*/SKILL.md`。使用 `git ls-files` 与目录枚举互相核对，严禁使用 `.gitignore` 藏匿孤立知识。
4. 明确本轮巡检覆盖清单与层级（已全面语义核查、仅结构检查、未覆盖或不适用）。

## 2. 规则对照与防弱化审计

- **高保护级别规则审阅：** 对照治理规范，核查关键自动化测试、CI/提交钩子配置、Guardrail 校验脚本（如 `Manage-Docs.ps1`）、核心 Requirements 及文档治理规则是否遭到私自弱化、绕过或注释。
  - 严禁因检查未通过而擅自放宽判据。
  - 检查工具与规则自身的合规演进必须具备明确的原因说明、影响范围评估和验证证据。
- **不可逆操作规范审阅：** 审查文档、方案与脚本中涉及的破坏性操作（数据库清理/非兼容降级、数据擦除、强制覆盖安装、`git reset --hard`、`git clean -fdx`、私钥清理等），核查是否均已显式标注【无法回滚/高风险】并声明更高层级的用户确认要求。
- **敏感信息脱敏审阅：** 检索所有正式文档、验证历史与归档记录，确认不存在未脱敏的真实硬件序列号、签名密钥文件、私钥密码或敏感凭据。

## 3. 逐篇核查内容边界与一致性

逐篇审阅文档正文，并跨文档横向搜索相同主题、问题编号、配置项、版本号与命令：

- **主题是否单一且职责清晰：** 每份文档是否严格聚焦其声明的核心问题；是否混入了本应由其他主文档负责的配置、步骤或规则。
- **正文是否重复维护：** 同一流程或事实是否存在两个相互竞争、各自更新的独立副本；除归档与交接方案保留必要上下文外，现行知识必须收敛至唯一主文档，其余位置保留必要摘要与内联链接。
- **问题状态是否冲突：** 核查 `quality.md`、主文档与 `verification-history.md`，确认已解决问题已彻底迁入历史归档，当前问题页仅包含未闭环条目；是否存在将未实测写成已通过、将部分通过写成全部完成的情况。
- **与最新真实状态一致性：** 将文档描述与当前源码、Gradle 配置、`libs.versions.toml`、Room Schema、测试套件及构建配置互相核对；发现“实现已有但文档未记”或“文档写了但代码未实现”的脱节现象，直接依据证据修正或登记缺口。

## 4. 索引与 Agent 可达性核对

- 核对 `docs/index.md`（总索引）与归档索引的分工：
  - 总索引呈现根入口与 `docs/` 下除具体归档页以外的正式文档；不链接自动注入的 Skill。
  - 归档索引（`docs/archive/index.md`，存在归档文档时生成）专门集中链接 `docs/archive/` 下的所有具体历史文档；目录为空时确认未预建空索引。
  - 检查可达性链路：从 `AGENTS.md` 能够顺畅访问总索引、各主文档及存在的归档索引中的每一篇文档；Skill 单独受管，不要求通过文档链接到达。
- 核查所有 Skill 的元数据字段（8 个治理字段）、名称、目录匹配性及 `description`（无尖括号、纯文本、1–1024 字符）。

## 5. 修正、记录与收尾交付

- **授权内修正：** 在所属主文档修复经证据确认的事实错误、链接失效与元数据不符；涉及新问题或阻碍按规范登记入 `quality.md`。
- **留存巡检记录：** 在 [验收与验证历史](../../../docs/verification-history.md) 中记录本次巡检基线、覆盖清单、关键发现、修正去向、验证证据与未覆盖项。
- **运行自动化验证与提交：**
  ```powershell
  pwsh -NoProfile -File scripts/docs/Manage-Docs.ps1 -Mode Sync
  pwsh -NoProfile -File scripts/docs/Manage-Docs.ps1 -Mode Check
  git diff --check
  ```
- 暂存改动并执行 `Manage-Docs.ps1 -Mode Check -Staged`，按 Conventional Commits 提交。
- 最终回复详细报告审计范围、发现问题数、修正项、未解决缺口及验证边界。
