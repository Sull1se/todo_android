# 项目文档影响与收尾

## 触发与阅读

所有任务在最终交付前，由 [AGENTS](../../../AGENTS.md) 要求强制执行**知识影响判断**。当任务产生了需要长期保留的新事实、决定、状态或证据时，使用本 Skill 指导收尾。

> **核心原则：** 这不是要求“每次任务都更新文档或 Skill”，而是要求“每次任务都判断是否需要更新”。
> - 纯查询、排查无结论或未改变任何事实的只读任务，无需新建清单、刷新日期或修改文档；在最终回复中简要说明无需更新的具体依据即可。
> - 若判断需要更新，必须列出更新检查清单（Checklist）并逐项执行。

从 [文档总索引](../../../docs/index.md) 定位主文档，按任务阅读 [文档维护规则](../../../docs/documentation.md) 的职责映射表。独立全量文档审计使用 `audit-project-docs`，日常任务收尾不擅自扩大为全项目巡检。

## 知识影响判断三问

在任务准备交付或进入收尾阶段时，逐项评估以下三个维度：

1. **Evidence 留存判断：**
   - 本次任务是否产出了需要长期保存的证据？（如自动化测试执行报告、真机插桩结果、手动验收反馈、APK 签名指纹/哈希核验、性能与视口度量数据、架构与安全决策记录等）。
   - 若是：必须将证据与具体日期、版本或提交绑定，按规范记入 [验收与验证历史](../../../docs/verification-history.md) 或相关主文档，严禁以口头保证代替实际证据。
2. **项目文档影响判断：**
   - 本次任务是否改变了项目当前事实、设计或状态？（如应用业务逻辑、界面与手势、排序规则、Room 数据模型与迁移、Gradle 依赖与 SDK、打包与签名命令、已知问题状态等）。
   - 若是：对照主文档职责映射表，更新对应的唯一主文档（如 `todo.md`、`development.md`、`quality.md`）；涉及敏感信息（如设备序列号、凭据）时必须严格脱敏。
3. **Skill 维护判断：**
   - 本次任务是否发现了现有 Agent 工作流程、角色职责边界、提示词指导或辅助脚本的缺陷或演进需求？
   - 若是：更新对应的 `.agents/skills/<name>/SKILL.md`，同步元数据与描述，确保 Agent 执行指南与实际项目约束保持一致。

## 任务收尾检查清单与执行

当判断需要更新时，按以下步骤列出清单并执行：

### 1. 主文档事实回写与不可逆操作审计
- 将最新确立的代码事实、配置、接口回写至所属主文档，不创建竞争性副本。
- 检查本次任务中是否存在无法回滚的操作（如破坏性数据清除、非兼容性数据库降级、生产设备应用卸载、清除未提交工作的 Git 操作等）；此类操作必须显式标记并确保已取得更高层级的用户确认。

### 2. 状态流转与问题关闭迁移
- 严格遵循 [文档维护规则](../../../docs/documentation.md) 的关闭即迁移机制：
  - 若 `quality.md` 中的未闭环问题（APP 或 DOC 编号）在本任务中实际达到了关闭条件，立即将其完整记录连同解决版本/提交、关闭日期、验证证据迁入 [验收与验证历史](../../../docs/verification-history.md)。
  - 在同一提交中从 `quality.md` 中删除整条记录，绝不标“已解决”继续留在当前问题页。
  - 未完成或尚待手动验收的问题，如实保留在 `quality.md` 并更新当前进度与下一步。

### 3. 高保护级别守护与防弱化校验
- 关键测试用例、Guardrail 校验脚本（如 `Manage-Docs.ps1`）、核心 Requirements 及文档治理规则拥有比普通业务代码更高的保护级别。
- 绝不允许因检查未通过而弱化、注释或删除测试与规则。若规则或脚本本身确有缺陷，说明修改原因、影响范围与验证方式，在既有授权内合规演进，不额外引入审批流程。

### 4. 自动化生成与提交验证
在项目根目录的 PowerShell 7 中执行标准收尾验证：

```powershell
pwsh -NoProfile -File scripts/docs/Manage-Docs.ps1 -Mode Sync
pwsh -NoProfile -File scripts/docs/Manage-Docs.ps1 -Mode Check
git diff --check
```

- 核对 `Manage-Docs.ps1 -Mode Sync` 产生的生成区差异，确保总索引（`docs:index`）、归档索引（`docs:archive`）与配置表（`docs:config`）准确无误。
- 暂存本次改动，执行暂存区专项校验：

```powershell
pwsh -NoProfile -File scripts/docs/Manage-Docs.ps1 -Mode Check -Staged
```

- 使用 Conventional Commits 提交（例如 `docs(update): sync documentation and evidence`），提交后执行 `git status --short` 复核工作区，确保不遗漏、不夹带无关变更。

## 交付与汇报

在任务最终回复末尾清晰汇报：
1. **知识影响判断结果**：逐项说明 Evidence、项目文档与 Skill 的判断依据与处理结论；
2. **文档与文件变更清单**：列出创建、修改、删除的具体文件；
3. **验证范围与证据**：明确说明本次实测通过的项目（如静态检查、测试用例、哈希核对）与未覆盖范围（如未连接设备、待手动验收）。
